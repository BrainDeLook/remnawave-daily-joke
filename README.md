# Remnawave Daily Joke

Локальная нейросеть на Raspberry Pi 5 раз в сутки придумывает анекдот по вашим примерам и записывает его в **announce подписки Remnawave**. Без платных API, облачной генерации, Telegram-ботов и отдельной установки Ollama.

Это новое небольшое дополнение Home Assistant OS, а не интеграция HACS. Ollama и модель работают внутри дополнения. Поддерживаются ARM64 (RPi 5) и AMD64.

## Установка в Home Assistant OS

1. Откройте **Настройки → Дополнения → Магазин дополнений → ⋮ → Репозитории** (в некоторых версиях интерфейса дополнения называются приложениями).
2. Добавьте репозиторий:
   ```text
   https://github.com/BrainDeLook/remnawave-daily-joke
   ```
3. Найдите **Remnawave Daily Joke** и нажмите **Установить**. Home Assistant скачает готовый образ из GHCR для вашей архитектуры. На RPi ничего компилировать не нужно.
4. Во вкладке **Конфигурация** заполните:
   - `panel_url`: HTTPS-адрес **своей** панели. Можно целиком вставить вашу секретную ссылку `/auth/login?имя=значение`.
   - `api_key`: API-ключ **Remnawave**, не ключ нейросети. В версиях с разрешениями нужны чтение и изменение **Subscription Settings**.
   - `cookie`: оставьте пустым, если используете секретную ссылку. Если защита требует явную cookie, укажите полную строку `имя=значение`. Авторизованную сессию администратора обычно указывать не нужно: API использует ключ.
   - `examples`: замените демонстрационные анекдоты на свои, например 5–10 коротких примеров. Это примеры стиля в запросе, а не дообучение.
   - `daily_time`: время, например `09:00`.
   - `timezone`: например `Europe/Moscow`.
5. Оставьте `dry_run: true`, запустите дополнение и откройте **Веб-интерфейс → Сгенерировать предпросмотр**. При первом запуске дождитесь загрузки модели. Новый анекдот появится на странице и в журнале. Кнопку можно нажимать повторно после завершения генерации — менять время не нужно.
6. Если анекдот устраивает, установите **`dry_run: false`**, сохраните и **перезапустите** дополнение. После наступления заданного времени оно изменит announce. При включении после заданного времени обновление выполняется сразу.
7. Включите **Запуск при загрузке**. Следующие дни работают автоматически.

**Все изменения конфигурации применяются после перезапуска дополнения.** Модель при обновлении и перезапуске не скачивается заново: она хранится в `/data/models`.

В веб-интерфейсе при `dry_run: false` доступна кнопка **Сгенерировать и опубликовать**. Она сразу обновляет анонс, независимо от расписания и сегодняшнего запуска. После успешного ручного запуска автоматический запуск сегодня пропускается; повторный ручной запуск разрешён. Незавершённая публикация повторяет сохранённый анекдот. Смена времени или обычный перезапуск не сбрасывают отметку выполненного дня. Интерфейс использует [Home Assistant Ingress](https://contributors.home-assistant.io/apps/guides/ingress/) без открытия порта на хосте; в Docker Compose ручной интерфейс недоступен.

> При `dry_run: false` анекдоты публикуются автоматически, без ручного одобрения. Качество юмора маленькой модели не гарантировано. Начните с предпросмотра. Если генерация, сеть или API дают ошибку, старый announce сохраняется (кроме случая, когда PATCH успел пройти, а проверка ответа не удалась).

## Модель и ресурсы RPi 5

По умолчанию — **Qwen2.5 1.5B** в стандартной квантизации Ollama. Это компромисс между русским языком и размером:

| Модель | Когда выбирать |
| --- | --- |
| `qwen2.5:0.5b` | Минимум памяти; связность и юмор слабее |
| `qwen2.5:1.5b` | Начальный вариант; желательно RPi 5 с 8 ГБ ОЗУ |
| `qwen2.5:3b` | Лучше потенциал качества, больше память и время; только если есть запас |

У 1.5B загрузка модели порядка 1 ГБ; реальное потребление RAM выше размера файла и зависит от контекста. На RPi 5 с 4 ГБ и нагруженным Home Assistant лучше начать с 0.5B. Число потоков генерации ограничено двумя, контекст — 4096 токенов. После генерации `keep_alive: 0` просит Ollama сразу выгрузить модель из памяти. Сам сервер остаётся запущен.

Оставьте несколько ГБ свободного диска: нужны образ Ollama, Python и модель. Это лёгкая генерация по расписанию, **не** крошечный по объёму дистрибутив. При смене модели старые файлы остаются в хранилище дополнения.

Интернет нужен для установки/скачивания модели и обращения к вашей панели. **Текст примеров и запросы на генерацию не отправляются в облачный LLM API.** Модель не запускает инструменты и не имеет доступа к API-ключу: ей передаются лишь примеры и несколько предыдущих анекдотов.

## Что именно меняется в Remnawave

Проверено по текущим публичным контрактам backend:

- `GET /api/subscription-settings` — чтение UUID и текущих заголовков.
- `PATCH /api/subscription-settings` — отправляются только `uuid` и `customResponseHeaders`.
- В настройках сохраняется **`announce: rwEncodeBase64:Русский текст анекдота`**. Remnawave сама преобразует его в `base64:` при выдаче подписки. Предварительно кодировать текст не нужно. Остальные заголовки сохраняются.
- После записи дополнение повторно читает настройки и проверяет announce.

Источник: [контракт обновления](https://github.com/remnawave/backend/blob/main/libs/contract/commands/subscription-settings/update-subscription-settings.command.ts), [модель настроек](https://github.com/remnawave/backend/blob/main/libs/contract/models/subscription-settings.schema.ts).

Это **глобальный announce в Subscription Settings**, а не отдельный баннер веб-страницы подписки и не `maxDevicesAnnounce` (сообщение о лимите устройств). Если External Squad переопределяет заголовки, глобальный анекдот может не отображаться у участников такого squad. VPN-клиент увидит новый текст при очередном обновлении подписки, если он поддерживает announce.

Перед каждой записью предыдущие настройки сохраняются в `/data/before-update.json`. История последних 60 анекдотов и дата обновления — `/data/state.json`. Эти файлы находятся внутри хранилища дополнения, а не в GitHub. Автоматического восстановления старых настроек нет: вернуть announce можно вручную в панели.

Если процесс прервётся после PATCH, при повторе используется тот же сохранённый анекдот, а не новый. Ошибки повторяются не чаще чем раз в 30 минут. Пропущенные дни не наверстываются пачкой. Одновременное редактирование заголовков в панели во время обновления лучше исключить: API не предоставляет здесь атомарного изменения одного поля.

## Cookie-защита

Дополнение не угадывает секреты и не отключает защиту. Оно открывает предоставленную вами секретную ссылку, сохраняет `Set-Cookie` в памяти и обращается к API с API-ключом. Либо отправляет явно указанную вами cookie.

Переходы HTTP запрещены: ни API-ключ, ни явная cookie не должны уходить на другой адрес. Если прокси отвечает редиректом, проверяйте канонический HTTPS-адрес и настройки доступа. Секретная ссылка может вернуть редирект после установки cookie — cookie будет сохранена, сам переход не выполняется. JS-проверки, CAPTCHA, TinyAuth/MFA автоматически не поддерживаются; для них нужен разрешённый администратором способ API-доступа.

Адрес панели должен быть корневым доменом или ссылкой `/auth/login`; панели под нестандартным URL-префиксом пока не поддерживаются. Проверка TLS всегда включена. Секреты не выводятся в журнал; ошибки содержат только безопасное описание. Не публикуйте конфигурацию и резервные копии HA: в них могут находиться ключ и секретная ссылка.

## Если у вас Home Assistant Container, а не HA OS

Скачайте репозиторий на Linux-хост с Docker Compose, скопируйте `options.example.json` в `options.json` и заполните поля. Затем:

```sh
docker compose up -d
docker compose logs -f
```

Compose по умолчанию использует готовый ARM64-образ для RPi 5. На x86-64 Linux создайте `.env` со строкой `ADDON_ARCH=amd64`.

По умолчанию включён предпросмотр. После изменения `options.json`:

```sh
docker compose restart
```

Удаление контейнера не удаляет модель и историю из именованного тома `joke-data`. `docker compose down -v` удалит их — без необходимости эту команду не используйте. Порты наружу не открываются.

## Проверка и ограничения

```sh
python -m unittest discover -s tests -v
```

Тесты используют поддельные API и не обращаются к вашей панели. GitHub Actions запускает тесты, собирает контейнеры для AMD64/ARM64, проверяет запуск Ollama/Python и публикует версионные образы в GHCR. Для установки в HA OS сборка на устройстве не нужна. Фактический запуск на RPi 5, установка в вашем HA и запись в вашу Remnawave требуют проверки на вашем устройстве. До этого не считать интеграцию аппаратно проверенной.

Проверяется длина, наличие русского текста, точные повторы примеров/истории. Это не полноценная проверка качества и безопасности юмора. Неудачная генерация повторяется до трёх раз. Локальные модели могут писать несмешно или повторять похожие сюжеты. Сначала улучшайте примеры; при наличии памяти попробуйте 3B.
